Use `$imagegen` for raster images; use `$remotion-create`, `$remotion-markup`, and `$remotion-render` for generated videos. Use `$service-access` for
live-account access.

## Workflow

1. Read the product context, brand guidance, existing assets, recent content, channel access, and available performance evidence.
2. Resolve the deliverable, channels, language, timing, CTA, destination, and tracking that materially affect the result.
3. Create one core concept, copy direction, hook, script, or brief, then adapt it to each channel. Preserve established language, tone, terminology,
   RTL behavior, claims, and brand assets.
4. Generate requested assets through the routed skills. Validate message continuity, legibility, captions, safe zones, mobile viewing, destination
   accuracy, and channel fit. Derive current specifications, policies, trends, and permitted audio from official platform guidance.
5. Deliver the content package with final copy, assets or asset briefs, channel variants, destinations, tracking, and unresolved assumptions.
6. Before a live action, present the exact channel, account, content, media, CTA, destination, publish time, and action type for approval.
7. After approval, perform only the approved action, read it back, and report its URL or platform ID, status, and scheduled or published time.
8. For performance reviews, separate observed evidence from inference and recommend the smallest measurable next iteration.

## Channel adaptation

- Adapt dimensions, pacing, copy, and interaction pattern to each channel's native form instead of cross-posting identical content.
- For short-form video, open with the message immediately legible on mobile and ensure it still works without sound.
- Use a tracked destination when the CTA expects action; omit it for awareness-only variants.
- Reuse the core idea; vary caption, duration, crop, and edit per channel.

## Approval and safety

- Local concepts, drafts, and generated artifacts are not permission to publish.
- Every upload, publish, schedule, edit, deletion, reply, or other live-account mutation requires exact user approval.
- Keep product claims grounded in authoritative project sources; do not invent results, testimonials, urgency, or offers.
- Use media, music, likenesses, and claims only when the project has a confirmed right to use them.

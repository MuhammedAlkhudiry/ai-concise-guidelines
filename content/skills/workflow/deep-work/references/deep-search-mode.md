# Deep-Search Mode

Use this when the answer depends on broad discovery, current facts, external prior art, niche details, or evidence spread across multiple source classes.

Deep-search is a coverage pass for knowledge. Search each relevant source class with enough variation to expose contradictory or missing evidence, and track the search well enough to explain coverage.

## Source Classes

Pick only the relevant classes:

- Local repo code, docs, generated files, tests, issues, plans, and project knowledge.
- Official docs, specs, standards, changelogs, release notes, package registries, and API references.
- Product pages, pricing pages, support docs, status pages, and policy pages.
- GitHub issues, pull requests, discussions, commit history, and examples.
- Academic papers, benchmarks, reports, public datasets, and reputable analysis.
- Connected apps or internal tools when they are the source of truth.

## Evidence Quality

Use primary sources for claims that shape the decision. Use secondary sources for orientation, examples, or market color, and label them as such when they matter.

Cross-check important claims across independent evidence when possible. When sources disagree, report the disagreement instead of smoothing it away.

Do not treat search result snippets, outdated examples, generated docs, copied blog posts, or passing tests as final proof when stronger evidence should exist.
